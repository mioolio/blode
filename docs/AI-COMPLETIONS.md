# AI 服务、预测与补全清单

C 标准库与声明式语义规则的目录格式见 [语言规则](LANGUAGE-RULES.md)。工程通过 `be.build.cStandard` 选择 C99／C11／C17／C23，工作区符号索引及 `language.index` 接口提供定义位置。C/C++ 补全、悬停、定义、引用和诊断优先由 clangd 回答，未安装时回退到宿主内置语言服务，见 [clangd](CLANGD.md) 与[内置语言服务](LANGUAGE-SERVICE.md)。内置 C/Arduino JSON 补全目录已删除；用户和外部 AI 仍可通过补全清单添加、覆盖和禁用用户条目。

内部开发版中，声明 `manifest.languages` 的模块拥有自己的默认清单。首选项与 AI 状态接口展示当前模块的条目，不改写宿主默认 JSON；用户条目和工作区索引仍保留。模块格式见[模块语言适配](MODULE-LANGUAGES.md)。

补全清单是声明式数据。用户可在“首选项 → 补全与 AI 预测”编辑，已认证的外部 AI 也可通过同一接口读写。模型服务、预测来源和语言清单分别配置；已有外部 AI 接口继续保留。

## 配置模型服务

在“首选项 → 补全与 AI 预测”的模型服务区域设置提供商、接口地址、聊天模型、预测模型和 API Key。当前提供 DeepSeek、通义千问、硅基流动和自定义兼容接口的配置预设；模型名称可以手动输入，连接检查会读取服务返回的可用模型。

DeepSeek 预设地址为 `https://api.deepseek.com`。远程兼容接口使用 HTTPS；本机自定义服务可使用 `http://localhost`、`http://127.0.0.1` 或 IPv6 回环地址。提供商预设只是初始配置，实际模型权限由用户的服务账号决定。

保存配置后点击连接检查。已有密钥只显示“已保存”状态，可以替换或删除。配置保存在宿主数据目录的 `model-service.json`；凭据单独加密保存，Windows 使用当前用户 DPAPI，其他平台使用本机密钥加密。公共状态返回 `hasKey`，不返回密钥明文。工程和组件分享不包含宿主模型配置与凭据目录。

使用模型服务提供补全：

1. 将“预测来源”设为“模型服务”，选择预测模型。
2. 在编辑器右键选择“AI 补全”，或按 `Ctrl+Alt+Space`，立即请求一次；需要持续预测时，再开启“自动 AI 补全”。自动开关默认关闭。

“预测来源”设为“外部 AI”时，沿用下文的请求／提交接口，由已连接的外部工具提供建议。两种来源都支持手动与自动触发；聊天服务、自动补全开关和常规补全清单分别配置。

## 问答与代码修改

编辑器右键可以向 AI 提问或请求修改，右侧显示会话、输入框、进度和工具操作结果。范围选择包括选区、当前文件、工程和目标电脑。外部只读头文件可用于提问；不能作为编辑目标。

| 范围     | 上下文与操作                                                       |
| -------- | ------------------------------------------------------------------ |
| 选区     | 选中文字及附近上下文；修改仅替换选择范围                           |
| 当前文件 | 当前文件内容；修改完整文件，保留其他文件                           |
| 工程     | 列出、读取工程文件；编辑模式可修改或创建工程文件                   |
| 目标电脑 | 明确启用后提供宿主文件、命令和工作台操作能力；工具结果保留在会话中 |

选区和文件修改在应用前核对原始文本与工程；用户或协作者已改动时，旧结果不会继续写入。协作编辑使用共享修订和用户身份；未启用草稿同步时，返回本地待应用修改。停止会话会取消当前请求，切换工程或范围会建立新的上下文。

目标电脑模式具备真实宿主操作能力。界面需要明确授权，自动化调用需要 `confirm: true`；具体工作台操作继续使用各自的确认参数。普通问答不会获得运行命令的工具。

### 模型与会话接口

| 方法              | 用途                                               |
| ----------------- | -------------------------------------------------- |
| `model.state`     | 读取提供商、模型、预测来源、版本与密钥存在状态     |
| `model.configure` | 保存配置和可选的新密钥；要求版本及 `confirm: true` |
| `model.test`      | 检查连接并读取模型列表                             |
| `ai.chat.start`   | 以明确范围及 `ask/edit` 意图创建或继续会话         |
| `ai.chat.state`   | 读取会话消息、工具结果、修改文件与状态             |
| `ai.chat.cancel`  | 取消指定会话                                       |

会话返回 `id` 和 `token`；读取、继续和取消时同时提供会话身份。配置使用 `revision` 避免迟到更新覆盖新设置。桌面与 Web 共用宿主实现，网页端设置的是服务端电脑的模型服务。

## 手动维护补全清单

首选项中的 JSON 包含 `useBuiltins` 和 `entries`：

```json
{
  "useBuiltins": true,
  "entries": [
    {
      "language": "cpp",
      "name": "board_init",
      "kind": "function",
      "detail": "void board_init(void)",
      "documentation": "初始化当前开发板。",
      "insertText": "board_init();"
    },
    {
      "language": "cpp",
      "owner": "Board",
      "name": "start",
      "kind": "method",
      "detail": "void start()",
      "insertText": "start()"
    }
  ]
}
```

- C／Arduino 在编辑器中使用 `cpp` 语言 ID。
- `kind` 可选 `function`、`method`、`variable`、`constant`、`type`、`keyword`、`snippet`、`property`。
- `owner` 存在时，只在对应的 `Board.` 等成员访问后显示。
- 同一 `language`／`owner`／`name` 替换用户或工程同名项；加上 `disabled: true` 可隐藏该条目。`useBuiltins: false` 保留用户项与工程符号解析；内置 C/Arduino 补全包已移除，不再有可关闭的内置清单。
- `insertText` 支持 Monaco 的 `${1:参数}` 片段语法。预测提示接口则接收普通文本，不解释片段占位符。
- 点击保存后立即生效；“恢复内置清单”清除用户覆盖，不改变 AI 预测开关。可展开“查看内置清单”查看当前模块的只读条目（内置补全包已为空）。
- 原有工程级 `blode.completions.json` 和头文件／宏解析继续工作。

清单最多 1000 项，配置总大小限制为 1 MB，保存在应用数据目录的 `ai-assistance.json`。它属于本机用户设置，不写入平台核心源码。修改带版本号，其他用户或 AI 同时更新时会提示版本冲突，刷新后重新合并，不会静默覆盖。

## 外部 AI 修改清单

沿用 [AI 管道](AI-PIPE.md) 的连接、令牌与 JSON-RPC 封包。以下示例展示 `method` 与 `params`；同名能力也通过 MCP 工具目录暴露。

1. 调用 `ai.state`，取得 `revision`、`predictionEnabled`、`predictionDelayMs`、`useBuiltins`、用户 `entries` 与只读 `builtins`。
2. 在原清单上合并变更，以取得的版本调用 `ai.configure`。

```json
{
  "method": "ai.configure",
  "params": {
    "revision": 0,
    "useBuiltins": true,
    "entries": [
      {
        "language": "cpp",
        "name": "LED_PIN",
        "kind": "constant",
        "detail": "当前板载 LED 引脚"
      }
    ]
  }
}
```

`entries` 是新的完整用户清单，提交前应保留不打算删除的项目。恢复默认使用 `ai.configure` 的 `{ "revision": 当前版本, "resetCatalog": true }`。AI 可让用户打开首选项，说明需要修改的条目；用户与 AI 使用同一个版本和校验规则。

## 手动与自动 AI 补全

| 触发方式 | 使用方法                                       | 自动开关关闭时           |
| -------- | ---------------------------------------------- | ------------------------ |
| 手动一次 | 编辑器右键“AI 补全”，或 `Ctrl+Alt+Space`       | 可以请求，不改变自动设置 |
| 自动补全 | 在首选项开启“自动 AI 补全”，输入后等待设定间隔 | 不创建自动请求           |

自动补全**默认关闭**。开启后，C／C++、注释、字符串、普通文本等编辑内容使用同一触发流程，不按语言、关键词或最少字数筛选。单个字符、中文、空格和换行均可触发；输入法组合期间等待文字提交，随后计算输入间隔。

在“首选项 → 补全与 AI 预测”设置输入间隔，默认为 **750 ms**，可选 **100–10000 ms** 的整数。继续输入会重新计时。间隔通过失焦或按 `Enter` 保存，输入每个数字时不会立即写入配置；旧配置缺少该字段时使用 750 ms。

结果显示为光标后的灰色文本。按 `Tab` 接受全部建议，撤销可恢复；`Ctrl+Space` 继续用于编辑器常规补全。继续输入、移动光标、切换文件、远程改动或按 `Escape` 会撤销旧建议；新请求核对当前工程、文件、模型版本和光标。失败重试时也会清除上一条灰色建议。

编辑区底部显示请求状态：正在生成、按 `Tab` 接受、暂无建议，以及缺少密钥、超时或服务错误。模型返回空文本时立即结束为“暂无补全建议”。请求等待超过约 16 秒会显示超时并取消；状态提示不打断输入。没有建议并不代表输入未触发。

### 配置接口

`ai.state` 返回配置；`ai.configure` 按当前 `revision` 更新以下字段，配置保存在宿主用户目录的 `ai-assistance.json`：

| 字段                | 类型与默认值            | 含义                               |
| ------------------- | ----------------------- | ---------------------------------- |
| `predictionEnabled` | `boolean`，默认 `false` | 是否自动触发；不限制明确的手动请求 |
| `predictionDelayMs` | 整数，默认 `750`        | 自动输入间隔，范围 `100–10000` ms  |
| `revision`          | 非负整数                | 读写配置的版本号，更新后递增       |

```json
{
  "method": "ai.configure",
  "params": {
    "revision": 3,
    "predictionEnabled": true,
    "predictionDelayMs": 1000
  }
}
```

关闭自动模式会取消自动请求。已明确发起的手动请求继续处理；调整间隔也不会把它变成自动请求。关闭自动模式不会修改模型服务或常规清单。

### 请求与外部工具接口

1. 编辑器触发 `ai.prediction.request`，提交当前工程、文件、模型版本、光标和附近上下文。自动调用省略 `manual` 或设为 `false`；单次手动动作显式携带 `manual: true`。自动开关关闭时，省略该参数的调用返回 `null`。
2. 来源为“模型服务”时，宿主调用预测模型；来源为“外部 AI”时，工具调用 `ai.predictions.poll` 获取请求。首次传 `{}`，后续可传 `{ "after": 上次返回的cursor }`。自动关闭时仍可轮询到手动请求。
3. 请求包含唯一 `id`、递增 `sequence`、`projectRoot`、`path`、`editorId`、`modelVersion`、`line`、`column`、`prefix`、`suffix`、可选的 `manual` 和过期时间。前后文各最多 12000 个字符，请求 60 秒后过期。
4. 外部 AI 生成**从光标开始追加的普通文本**，调用：

```json
{
  "method": "ai.prediction.submit",
  "params": {
    "requestId": "从待处理请求取得的 id",
    "text": "return 0;"
  }
}
```

提交的建议最多 16384 字符。旧请求、已取消请求和切换工程后的结果会被拒绝；客户端也核对模型版本与光标。

| 方法或事件                          | 用途                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| `ai.prediction.request`             | 发布自动或显式手动上下文，返回请求或 `null`                  |
| `ai.predictions.poll`               | 读取待外部工具处理的请求；模型服务正在处理的请求不会重复发布 |
| `ai.prediction.submit`              | 外部工具提交指定请求的非空建议                               |
| `ai.prediction.read`                | 读取建议；模型的空响应返回 `text: ""`，生成错误返回对应错误  |
| `ai.prediction.cancel`              | 按 `editorId` 及可选 `requestId` 取消                        |
| `status.aiPredictionRequested <id>` | 新请求已创建                                                 |
| `status.aiPredictionReady <id>`     | 建议已就绪，包括模型的空结果                                 |
| `status.aiPredictionFailed <id>`    | 模型请求失败，可通过读取接口取得错误                         |

桌面、Web、AI 管道和 MCP 使用同一配置和请求校验。编辑器显示结果之前核对当前快照；取消与迟到响应不会恢复已失效的建议。

## 当前验证

模型配置、凭据边界、请求取消、会话身份和修改范围已有自动化测试。独立隐藏 Electron 测试应用使用假模型服务，通过提供商设置、真实编辑器选区提问、本地精确替换、一次撤销恢复、中英文菜单解析、外部头文件只读定位及窄屏聊天布局；切换模型时的 Monaco 取消日志已定向修复并重测。

本轮有 **46 项相关自动化测试通过**，覆盖默认开关、旧配置迁移、间隔范围与持久化、手动参数、全输入触发、输入法组合、设置刷新竞态、取消与迟到结果、失败与空响应、会话及修改边界；TypeScript 类型检查通过。

独立隐藏 Electron 应用使用真实 Monaco 和假模型服务，**18 个场景通过**，保存了 15 张截图，运行错误与未处理异步错误均为空：

- `//这是什么` 中文注释的手动补全，自动模式关闭时仍可请求。
- 真实 `Ctrl+Alt+Space` 和 `Tab` 按键、多行整段接受与一次撤销。
- 自定义 1200 ms 间隔，以及中文、单字、空格、换行、字符串输入。
- 继续输入取消、迟到结果失效、失败重试清除旧建议、缺少密钥与空结果反馈。
- 选区问答、本地精确替换、中英文菜单、外部只读头文件和窄屏布局。

首选项另有独立界面检查，覆盖默认值、失焦保存、`Enter` 保存、越界校验、保留未保存 JSON 与 350px 布局。输入法组合阶段的触发控制由自动化事件测试覆盖；不同输入法的实际输入体验继续人工验收。

Windows 宿主此前对 DeepSeek 发送固定的合成连接文字并收到严格 `OK` 回复；该连接检查未发送工程源码，没有调用工具或修改文件。本轮补全回归使用假服务，没有调用付费模型或用户硬件。不同模型的建议质量、长会话及大型工程修改继续人工验收。

# 组件库

组件库将第三方源码和依赖保存在当前工程，供编译器使用。入口为 **运行 → 组件库**，桌面版和 Web 版使用同一套宿主服务。

本文对应已合入 `main` 的内部开发预览。功能随源码提供，本次没有发布新的桌面或 Web 二进制包。

## 支持范围

| 工程            | 支持的组件                          | 构建方式                                                                                              |
| --------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `Esp32_S3_CAM`  | Arduino 库、原生 C/C++ 源码组件     | Arduino CLI 使用工程库目录，并编译原生组件源码                                                        |
| `STM32F103C8T6` | 原生 C/C++ 源码组件及适用的汇编源码 | 将源码和头文件目录交给当前 GNU Arm / Arm Compiler 构建流程                                            |
| 第三方运行时    | 由运行时作者实现                    | 接收宿主派生的 `ProjectBuildInputs.components`，见[模块开发指南](RUNTIME-PLUGINS.md#项目组件构建输入) |

STM32 原生构建不提供 Arduino 框架。导入 Arduino 库不等于获得 STM32 Arduino 支持；构建遇到这类库会明确报错。库的芯片、ABI、外设与框架要求仍需与工程匹配。

## 查看与安装

### 项目依赖与平台内置库

打开组件库后，**项目依赖**列出工程管理的库、版本、来源、相对路径和声明依赖。**平台内置**从宿主已安装的 Arduino 平台包读取库信息，供查看，不复制进工程，也不能通过这里删除。

窗口首次打开只读取本地状态，不搜索网络。未打开工程时可以查找在线库，安装、导入和移除需要先打开工程。

### 在线库

1. 打开**查找库**，输入名称或关键词并点击**搜索**。
2. 选择结果，在版本菜单中指定版本；依赖列表随版本更新。
3. 点击**安装到项目**。窗口显示下载、校验、安装进度与错误输出。

搜索使用 Arduino 官方维护的[库索引](https://downloads.arduino.cc/libraries/library_index.json.gz)。索引同时收录 Arduino 与社区作者的库，“来自官方索引”不表示每个库都由 Arduino 编写。

安装会递归解析版本约束，复用符合要求的工程依赖或平台库，并下载缺少的依赖。归档按索引中的大小和 SHA-256 校验。冲突、缺少可用版本或重复顶层库会返回错误，不自动覆盖现有组件。搜索结果有数量上限，可通过更具体的关键词缩小范围。

### 本地文件夹与 ZIP

1. 打开**本地导入**，选择文件夹或 ZIP；也可直接输入宿主绝对路径。
2. 核对来源类型与路径，点击**导入到项目**。
3. 返回**项目依赖**查看导入结果，保存源码后编译。

文件选择器始终浏览**运行 Blode Studio 服务的目标电脑**。浏览器连接远端宿主时，选择的不是浏览器所在设备的文件。ZIP 可包含一层统一的顶层目录。

- 含 `library.properties` 的组件按 Arduino 库处理，读取名称、版本和 `depends`。
- 其他包含可识别源码或头文件的目录按原生组件处理；示例、测试和文档目录不加入原生编译源文件清单。
- 导入会复制文件，不执行库附带的安装脚本或构建脚本，也不修改全局 Arduino 库目录。
- 本地库没有缺失依赖时可离线导入；声明的依赖尚未满足时，仍会访问 Arduino 索引解析和下载。

## 工程目录与分享

```text
project/
├─ be
├─ blode.components.json
├─ libraries/
│  └─ ArduinoLibrary/
│     ├─ library.properties
│     └─ src/
└─ components/
   └─ NativeLibrary/
      ├─ include/
      └─ src/
```

`blode.components.json` 是版本为 `1` 的组件清单，记录库身份、版本、来源、工程相对路径、源码、头文件目录、依赖和文件摘要。名称会转为适用于跨平台目录的形式；原始显示名称仍保留。

分享或提交工程时，一并保留清单和对应的 `libraries/`、`components/` 目录。源码已复制到工程，不依赖原导入文件夹的位置。接收者仍需安装工程所选编译器和平台包；平台内置库及工具链不随组件清单复制。

编译前，宿主校验清单与工程内路径，再派生组件输入。组件文件和清单参与构建指纹，变更后原有构建会失效。不要把派生的 `build.components` 写入 `be`；工程配置与组件清单分别维护。

## 移除与错误处理

在**项目依赖**中点击库后的移除按钮，确认后删除该受管目录并更新清单。以下情况会拒绝移除：

- 其他已安装组件仍依赖该库。
- 导入后的文件已被修改、删除或新增，无法与记录的文件摘要一致。
- 目录被替换、出现符号链接，或工程在操作期间切换。

先保存需要保留的修改、检查依赖关系，再处理对应目录。移除一个库不会递归清理它曾经安装的依赖，也不会删除平台内置库。需要切换已安装库版本时，当前流程是移除后重新安装；受删除保护的组件须先处理其修改或依赖者。

| 现象                   | 处理方式                                                     |
| ---------------------- | ------------------------------------------------------------ |
| 同名库已经存在         | 查看项目依赖；当前操作不会覆盖已有目录或版本                 |
| 组件属于平台内置库     | 使用平台提供的版本，或调整工程工具链与平台包                 |
| 依赖版本不满足         | 查看错误中的库名和约束，选择兼容的库版本                     |
| ZIP 或路径被拒绝       | 使用普通目录或 ZIP，移除目录跳转、符号链接和不支持的归档条目 |
| 工程发生切换           | 在目标工程重新打开组件库，再执行操作                         |
| STM32 提示需要 Arduino | 使用原生组件，或由支持该框架的运行时负责构建                 |

## AI 与运行时集成

`components.state`、`components.search`、`components.install`、`components.import`、`components.remove` 同时映射为 JSON-RPC 和 MCP 工具。安装、导入、移除均要求 `confirm: true`，以及从 `components.state` 取得的 `expectedProjectRoot`。宿主在操作开始与提交时核对目标工程。

完整参数和示例见 [AI 接口](AI-PIPE.md#组件库接口)。运行时通过 `build(config, build)` 接收宿主派生的组件路径清单，将对应源码与头文件目录交给构建流程；字段说明见[项目组件构建输入](RUNTIME-PLUGINS.md#项目组件构建输入)。

本轮相关修复还包括 ESP32-S3 留空 USB 序列号时的 OpenOCD 自动选择，以及编译时追加 `extra_flags`、保留平台原有 `-c` 等参数。它们不代表实机 USB-JTAG 验收完成，硬件状态见[硬件调试指南](HARDWARE-DEBUGGING.md)。

# 自定义设备模块

STM 自定义和 ESP 自定义面向需要自行设置设备参数的工程。模块不维护型号白名单，实际通信和编程由安装在宿主电脑上的 ST-Link、esptool 或 Arduino 工具完成。它们不代表所有芯片已通过实机验证。

## 选择与配置

在目标设备中选择 **STM 自定义** 或 **ESP 自定义**。配置随工程 `be` 文件保存，也可从组件库导出模块 ZIP。两个模块都独立声明运行时、工具、语言、布局、界面和约束，发行包包含编译后的 JavaScript，不需要宿主源码。

| 参数       | STM 自定义                    | ESP 自定义                         |
| ---------- | ----------------------------- | ---------------------------------- |
| 型号       | 用户填写的工程型号            | esptool 芯片标识；`auto` 自动检测  |
| 连接       | ST-Link 序列号、SWD 频率      | 串口、烧录波特率                   |
| 容量与布局 | Flash 容量、应用和预留区      | Flash 容量、应用和数据区           |
| 地址       | Flash 基址；默认 `0x08000000` | Flash 基址、Bootloader、分区表地址 |
| 编译       | 自定义构建程序及参数          | Arduino FQBN，或自定义构建程序     |
| 语言       | 模块声明的 C / C++            | 模块声明的 C / C++ / Arduino       |

自定义模块由用户显式选择，不改变现有 ESP32-S3 和 STM32F103C8T6 的自动识别规则。自定义模块当前不提供统一硬件调试器。

## STM 构建

可使用已有 CMake、Make 或其他构建程序。构建程序通过独立参数启动，不使用 shell 命令串。

示例：

```json
{
  "buildExecutable": "cmake",
  "buildArguments": "[\"--build\",\"{root}/build\",\"--config\",\"Debug\"]",
  "firmware": "build/firmware.bin"
}
```

参数字符串为 JSON 数组，支持 `{root}`（工程根目录）、`{output}`（Blode 构建目录）和 `{entry}`（编译入口）。输出固件路径相对于工程根目录。构建程序为空时，STM 模块验证并使用已有的 `firmware.bin`。

CPU、启动文件、链接脚本、编译器和 ABI 由该构建工程负责；Blode 不把其他型号套用到 F103 的编译参数。

## ESP 构建

构建程序为空时使用 Arduino CLI 和所填 FQBN，例如 `esp32:esp32:esp32c6`。对应 Arduino core 必须已安装。Blode 建立独立 sketch 暂存目录，保留源码位置映射，生成分区表并收集 BIN 产物。

Bootloader 地址设为 `auto` 时，经典 ESP32 使用 `0x1000`，其他目标使用 `0x0`；可以填写显式地址。其他架构或特殊启动链应按其工具要求配置。指定自定义构建程序后，使用其输出的单个固件 BIN。

## 不打开工程直接烧录

从固件烧录窗口选择自定义模块、连接器、容量和地址，选择 BIN、HEX 或 S-record。HEX 和 S-record 的地址来自文件；BIN 的地址由用户填写。烧录前会验证已选文件快照与实际文件的哈希。

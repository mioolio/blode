# Git 管理

入口：“视图 → Git 管理”或项目资源标题栏的分支图标。桌面与 Web 使用目标电脑上的 Git。

## 管理方式

默认使用 Blode 独立仓库，版本历史保存在工程的 `.blode/git/`，当前工程目录作为工作区。已有 `.git` 或父目录仓库只显示为可选共享仓库，启用“与其他软件共用仓库”后才参与管理。

| 模式               | 历史与配置                                        | 适用场景                             |
| ------------------ | ------------------------------------------------- | ------------------------------------ |
| Blode 独立仓库     | `.blode/git/`，独立提交身份、分支、索引、远端配置 | 仅在本软件中管理工程                 |
| 与其他软件共用仓库 | 工程或父目录的现有 `.git`                         | 与命令行、其他编辑器使用同一版本历史 |
| 停用 Git 管理      | 保留现有历史，界面停止显示 Git 文件状态           | 暂时关闭版本管理                     |

“管理方式”页可切换模式、停用或恢复管理。两个模式的历史分别保留，切换模式使用各自的索引和分支。

独立仓库使用本地配置，不读取系统或全局 Git 配置；提交身份在“提交身份”页设置。远端认证可在该仓库配置 SSH 或凭据帮助器。共享模式沿用现有仓库及目标电脑的 Git 配置。

独立仓库不记录自己的 metadata、构建产物、缓存或语言索引。工程内的语言规则等源码配置仍可单独加入版本管理。若还使用外部 Git 工具，可在其忽略配置中加入 `.blode/git/` 与 `.blode/git-management.json`。

## 停用与删除历史

- **停用 Git 管理**：保留历史，之后可以恢复。
- **删除 Blode 历史记录**：只删除 `.blode/git/`，保留当前代码及其他仓库。
- **删除共享仓库历史**：仅在共享模式中显示。界面列出实际 `.git` 路径，输入完整仓库根目录并确认后删除；其他 Git 工具也将失去这份历史。当前代码保留。

链接工作树或子模块使用 `.git` 文件时，历史删除交由 Git 工具处理。

## 图形工作流

1. 在“管理方式”中启用独立仓库，或选择共享仓库。
2. 在“提交身份”中填写名称与邮箱。
3. 在“修改”中检查对比，按文件暂存或全部暂存。
4. 输入提交说明，提交已暂存修改。
5. 在“分支”中创建或切换分支。
6. 在“远端”中设置 HTTPS、SSH 或本地仓库地址，执行获取、快进拉取或推送。

干净文件不显示状态；`M` 表示修改，`U` 表示未跟踪，`A` 表示已暂存新文件，`D` 表示删除，`R` 表示重命名，`!` 表示冲突。对比区可分别查看工作区和暂存区；状态随工程文件变化和 Git 操作更新。

共享模式打开仓库子目录时，列表限于当前工程，工程外修改显示计数。工程外已有暂存内容时，应从仓库根目录检查后提交。切换分支或拉取前保存共享编辑内容。命令窗口继续提供完整 Git 命令操作。

## 接口

- `git.status` / `gitStatus()`：读取管理模式、文件状态、分支和远端。
- `git.diff` / `gitDiff({path, staged?})`：读取工程相对路径的对比。
- `git.action` / `gitAction(request)`：执行命名操作。

管理操作示例，每次调用使用其中一个请求：

```json
[
  { "action": "init" },
  { "action": "setMode", "mode": "shared", "confirm": true },
  { "action": "setMode", "mode": "disabled", "confirm": true },
  { "action": "removeRepository", "target": "isolated", "confirm": true }
]
```

删除共享历史还需 `target: "shared"` 与精确的绝对 `repositoryRoot`。`GitStatus.mode` 区分 `isolated`、`shared` 和 `disabled`；`ownedHistory` 表示存在本软件历史，`sharedAvailable` 表示可选择现有共享仓库。

其他操作包括 `stage`、`unstage`、`commit`、`createBranch`、`checkout`、`remoteSet`、`remoteRemove`、`configure`、`fetch`、`pull`、`push`。模式切换、历史删除、提交、移除远端、拉取和推送需要 `confirm: true`。

## 实现与验证

Git 子进程通过参数数组运行，清除继承的 `GIT_DIR`、索引等 Git 环境变量，关闭 hooks、fsmonitor 与自动签名。拉取采用快进方式，推送发送当前 HEAD 到明确分支。

测试使用临时仓库，覆盖独立历史、共享历史、停用与删除、暂存、提交、分支，以及本地裸仓库的推送和拉取。Linux 路径与命令参数已按跨平台方式实现，本轮尚未在 Linux 实机验证。

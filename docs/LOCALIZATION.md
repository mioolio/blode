# 界面国际化

## 支持语言

在 **首选项 → 常规设置 → 界面语言** 中切换。列表使用各语言自己的名称，设置保存在当前客户端；主窗口和同源独立窗口同步语言偏好，不改变协作者的个人选择。

| 语言             | 标识    | 选择器显示         |
| ---------------- | ------- | ------------------ |
| 简体中文         | `zh-CN` | 简体中文           |
| 繁体中文         | `zh-TW` | 繁體中文           |
| 英语             | `en`    | English            |
| 日语             | `ja`    | 日本語             |
| 韩语             | `ko`    | 한국어             |
| 德语             | `de`    | Deutsch            |
| 法语             | `fr`    | Français           |
| 西班牙语         | `es`    | Español            |
| 葡萄牙语（巴西） | `pt-BR` | Português (Brasil) |
| 意大利语         | `it`    | Italiano           |
| 俄语             | `ru`    | Русский            |
| 阿拉伯语         | `ar`    | العربية            |
| 印地语           | `hi`    | हिन्दी             |

首次启动根据浏览器或系统语言选择。已保存的偏好优先；`en-US`、`en-GB` 等映射到英语，`zh-Hant`／`zh-HK` 等映射到繁体中文，葡萄牙语地区变体使用巴西葡萄牙语。未支持的语言回退英语。

## 覆盖范围

- 主工作台菜单、欢迎页、工程操作、首选项、编译设置、组件库、Git、串口、资源与调试界面。
- 签名状态、安装确认、应用错误与状态提示。
- 编辑器常用右键菜单：定义、声明、实现、引用、格式化、重命名、剪贴板等。
- 桌面托盘菜单及 AI／自动化接口的语言选择参数。
- 官方 Personalization 扩展保留独立清单和语言文件。

阿拉伯语使用从右到左的界面方向；源码编辑器、终端、代码、路径与原始工具日志保持从左到右。Monaco 其他内部界面、自动化工具说明及没有相应译文的第三方扩展可回退英文。编译器、GDB 和系统命令的原始诊断不改写。

新增语言使用机器翻译建立初版，经过词条完整性、技术标记与程序行为检查；专业术语和母语表达仍欢迎社区校对。

## 代码入口

| 文件                                    | 职责                                               |
| --------------------------------------- | -------------------------------------------------- |
| `src/shared/locales.ts`                 | 唯一语言注册表、原生名称、地区映射、方向与托盘文案 |
| `src/renderer/locales/<标识>.json`      | 每种语言的完整界面词条                             |
| `src/renderer/localization.ts`          | 词条解析、英语回退、语言包加载缓存                 |
| `src/renderer/i18n.tsx`                 | React 上下文、个人偏好、窗口同步和文档方向         |
| `src/renderer/editor/menu-labels.json`  | 编辑器原始菜单标题到稳定词条的映射                 |
| `src/renderer/editor/localizeMonaco.ts` | 更新菜单标题，保留命令、条件和快捷键               |
| `src/renderer/styles/i18n.css`          | RTL 与源码／终端方向隔离                           |

简体中文与英文为基础字典；其他语言使用明确的动态导入，每种语言生成独立构建资源。切换时先加载再提交；并发请求只保留最后一次选择。应用运行不依赖在线翻译服务，已安装语言可以离线使用。

## 新增与维护词条

1. 在英文和简体中文基础字典添加相同的稳定键，再补齐其他语言文件。
2. 组件调用 `t('命名空间.功能')`，不将翻译后的文字作为数据标识。
3. 保留配置字段、相对路径、文件名、URL、格式化占位符与快捷键原文。
4. 使用中性、简短、面向操作的表达；避免重复项目名、型号或说明。
5. 运行 `npm run typecheck` 和语言测试，再检查生产构建是否包含语言资源。

```powershell
node --import tsx --import ./tests/register-styles.mjs --test tests/locales.test.ts tests/multilingual.test.ts tests/monaco-locale.test.ts
```

## 扩展开发

扩展在自己的 `manifest.json` 中声明 `locales`，路径相对于扩展根目录。扩展 UI 从宿主上下文读取 `locale`，优先使用对应字典，再回退 `en`。扩展无需导入宿主源码或访问宿主 JSON 文件。

语言文件属于扩展签名载荷。修改或新增翻译后，应更新扩展版本并重新签署 `obe`。详见[通用扩展](GENERAL-EXTENSIONS.md)和[组件签名](PACKAGE-SIGNING.md)。

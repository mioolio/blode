# 工作台功能总览

本文对应截至 2026-11-01 的 `main` 源码。已构建的 0.3.5.9 附件早于多语言和最新 ST-Link 修复；完整状态见[实现与验证](STATUS.md)，逐次变更见 [CHANGELOG](../CHANGELOG.md)。

## 编辑与工程

- 欢迎页和最近工程；打开工程后可返回首页，或保存并关闭工程。
- 预览标签在修改或 `Ctrl+S` 后固定；标签栏横向滚动，关闭未保存内容提供保存、放弃、取消。
- clangd 提供 C/C++ 补全、悬停、声明／定义／引用、诊断、格式化和代码操作；不可用时使用工作区索引。
- 工具链头文件可跨目录定位并以只读标签打开；图片支持滚轮缩放，音频和视频使用媒体预览。
- 编辑区更多操作可配置并打开宿主 VS Code；磁盘保存通过共享文件监听同步。

见[工程配置](PROJECTS.md)、[源码定位](SOURCE-NAVIGATION.md)、[资源预览](ASSET-PREVIEW.md)和 [VS Code](vscode.md)。

## 编译、设备与交付

**生成 → 编译设置** 只配置当前编译入口：Debug／Release、体积优化、编译器版本及可展开的 C／C++ 覆盖。多个命名入口通过生成菜单选择；单入口直接编译。设备连接与编译分离。

**生成 → 组件库** 管理设备模块与工程组件。设备模块支持搜索、分页、加载目录／ZIP、打开所在位置和导出；状态为正常、异常或危险。工程组件支持 Arduino 搜索、依赖安装、导入和独立分享。

**首选项 → 编译与工具链** 管理可下载版本和安装；**工具链与导出** 列出实际工具并重新收集清单、哈希和 ZIP。任务输出区分别显示下载、安装、收集、压缩及校验进度。Windows x64 的 ST-Link 1.9.0 已接入下载安装，版本目录也参与识别和调试工具查找。

工程 ZIP 收集可解析的外部源码、头文件与库并改写副本。固件工具支持 BIN／Intel HEX／S-record；STM32 有匹配产物时可另导出 ELF。预编译 BIN／HEX／S-record 可以在未打开工程时烧录。ESP32 导出按实际启动、分区和应用镜像组合；地址规则见[离线交付](OFFLINE-DELIVERY.md)。

## 工作区与串口

运行时及设备连接收纳在左下方，工程文件和构建资源统计共用底部资源页。目标设备、底部面板可关闭并从视图菜单恢复；编译自动打开输出。

串口面板支持 UTF-8／HEX、换行方式、波特率、数据位、校验、停止位与流控；日志独立滚动并保留阅读位置。设备初始化后缓存，手动刷新或 Windows 系统设备事件触发更新。

多个终端分别持有 PowerShell／系统 Shell 会话，可切换或单独结束。Git 默认使用工程独立历史，可显式启用已有仓库，提供差异、暂存、提交、分支及远端操作。见 [Git](GIT.md) 和[协作](COLLABORATION.md)。

## 独立硬件调试

主工作区从 **调试 → 硬件仿真** 打开独立窗口；Web 请求新标签。调试窗口顶部使用连接、调试、视图和工具菜单，内容按反汇编、寄存器、内存、固件和日志组织。

- STM32：ST-Link/SWD、GNU Arm GDB、单步、调用栈、批量断点和 SRAM 等长指令编辑。
- ESP32-S3：原生 USB-JTAG + OpenOCD，或烧录底座 UART GDB + runtime stub 固件；当前不支持 Xtensa 指令写入。
- 内存区将地址、长度与读取操作放在一起，暂停后采样。
- 成功构建自动关联匹配的 ELF；手动符号文件优先。连接本身不自动烧录。

ESP32-S3 + CH340 的计数器参考固件已完成真实调试。最新 STM32 验证完成芯片识别和工具 ZIP 迁移；SRAM 指令修改仍待实机验收。详见[硬件调试](HARDWARE-DEBUGGING.md)。

## 协作、AI 与语言

共享文件、工具页和面板通过统一注册表同步。新标签不抢焦点；关闭事务同步所有端，未保存内容先确认。成员注意力、头像堆叠、阅读范围过渡、按用户撤销、冲突报告和最新日志回放共用宿主状态。

AI 可使用配置的模型服务或外部接口。右键／`Ctrl+Alt+Space` 手动补全，自动预测默认关闭，可设置输入间隔；注释、代码与普通文本都可触发。问答与修改限定选区、文件、工程或明确授权的宿主范围。

界面支持 13 种语言，README 提供对应介绍；切换与扩展语言独立维护。官方 Personalization 示例提供自包含外观、语言及设置资源。见[AI](AI-COMPLETIONS.md)、[国际化](LOCALIZATION.md)和[扩展开发](GENERAL-EXTENSIONS.md)。

## 关闭与运行形态

桌面右上角关闭默认回托盘，单击／双击恢复；文件或托盘菜单退出结束应用，退出时检查修改。关闭到托盘的配置保存在 `desktop-lifecycle.json`。

Windows 提供桌面便携 EXE、自带 Node 的 Web EXE，以及需要 Node.js 24+ x64 的精简 Web ZIP。Web 操作目标电脑的文件和硬件。源码开发、端口自动避让、启动恢复和发行构建见[开发说明](DEVELOPMENT.md)与[发行构建](RELEASING.md)。

# 工程、组件与离线工具交付

本文说明工程、组件、设备模块和工具链 ZIP 的用途、生成内容、导入方式及验证范围。桌面端和 Web 端共用宿主实现；Web 端的文件选择指向运行服务的目标电脑，导出文件由浏览器下载。

## 交付方式

| 类型         | 使用场景                       | 包含内容                                                                   | 接收方操作                             |
| ------------ | ------------------------------ | -------------------------------------------------------------------------- | -------------------------------------- |
| 工程 ZIP     | 分享可继续开发的工程           | 工程文件、可归档的外部源码／头文件／库、迁移后的构建配置、依赖清单         | 解压，打开工程，选择本机工具版本并编译 |
| 组件 ZIP     | 分享选定组件及其配置           | 当前组件源码、自定义源文件／包含目录、组件元数据、已管理的递归依赖及校验值 | 在组件库中导入 ZIP                     |
| 设备模块 ZIP | 分享 ESP、STM 或第三方设备模块 | 模块声明、独立运行时代码、语言清单、界面与资源                             | 解压到宿主插件目录，重启宿主           |
| 工具离线 ZIP | 下载一次，在目标电脑离线安装   | 指定版本的发布归档、发布元数据、平台与架构、文件大小及 SHA-256             | 在工具版本中选择“导入离线包”           |

工程包不会顺带复制整套 SDK。所需 Arduino core、编译器家族与版本保存在工具需求清单中，可通过单独的工具离线包准备环境。

## 工程打包

### 依赖来源

打包器同时使用工程文件和成功构建的依赖记录：

1. 工作区文件、`be` 的入口和显式文件清单。
2. Keil `uvprojx` 的源文件、包含目录和 scatter 文件。
3. C／C++ 字面量包含及能够直接解析的本地常量宏包含。
4. 编译器生成的 `.d`，以及构建目录中的 `compile_commands.json`、`.rsp`、`.response`、`.lnp`。
5. 命名编译目标各自的 `.blode/targets/<id>/build` 和成功构建状态。

STM32 的 GNU Arm 和 Arm Compiler 6 编译现在生成 `.d` 记录。命名目标的记录分别判断是否有效；一个目标过期不会使另一个目标的依赖记录失效。构建失败、工程状态过期或记录中的依赖在构建后发生变化时，该次构建记录不再作为可迁移依赖证据。

同名头文件按各源文件的实际编译依赖解析，避免不同编译单元使用不同 `board.h` 时串联。无法解析的动态宏、缺失文件和未知绝对构建路径仍会出现在清单中，并阻止普通的完整导出。界面可明确选择导出带问题清单的工程。

### 目录与迁移规则

```text
project/
├── be
├── src/
├── components/
├── dependencies/
│   └── <路径摘要>-<原目录名>/
│       ├── board.h
│       └── library.a
└── .blode-share/
    └── manifest.json
```

- 外部文件归档到 `dependencies/`，目录摘要避免不同来源同名目录互相覆盖。
- 在导出副本中重写源码包含、Keil 文件引用和 `be` 入口；原工程不修改。
- 可定位到已归档文件的 CMake 路径使用 `CMAKE_CURRENT_LIST_DIR`；Make 文件使用生成的 `BLODE_PACKAGE_DIR` 定位自身目录。
- 主工程、子工程及命名目标内的配置均保留编译器家族与版本，移除本机工具绝对路径和设备连接标识。
- 由托管 SDK 或目标专用工具目录提供的依赖记录为工具需求，不复制到源码包中。
- `.git`、构建缓存、工具目录、宿主配置目录、模型凭据及常见密钥配置不归档。`.env.example` 等模板保留；`src/core/model-service/` 这类源代码目录正常保留。

清单记录每个归档文件的目标路径、外部依赖标记、大小和 SHA-256，以及工具需求、问题列表和是否完整。源码中自定义构建脚本、任意程序动态读取的文件，以及编译器未记录的运行时资源，仍需要显式加入工程或构建清单。

### 文件清单性能

依赖与问题清单按可见窗口渲染，滚动时只更新当前行与少量缓冲行。固定行高、路径省略和完整路径提示减少大列表的重复布局。打包弹窗移除了背景模糊合成；大屏采用宽布局，窄屏保留独立滚动。

## 组件包

在组件库选择组件后导出。导出前先保存工程配置；包中使用当前磁盘源码重新计算哈希，支持导入后经过修改的组件。

```text
blode.components.package.json
components/<id>/...
```

根清单的主要字段：

```json
{
  "format": "blode-components",
  "version": 1,
  "components": [],
  "dependencies": [],
  "directories": []
}
```

`components` 保存工程内组件的名称、类型、版本、来源、自定义源文件、包含目录、依赖与逐文件哈希。已管理的依赖按名称和版本约束递归纳入；不满足约束时停止导出。尚未在工程内管理的依赖保留在 `dependencies` 中，导入时沿用组件库的解析流程。

`directories` 保留用户配置的空包含目录。已被删除或超出组件目录的配置路径会在导出时报告。导入阶段先验证所有路径和内容，再统一写入暂存目录；任一组件写入失败时回滚整个组件包，不留下半套安装。

组件包兼容原有组件 ZIP 导入入口。普通 Arduino ZIP、标准组件目录和完整组件包会按各自的清单识别；包内代码是否支持某个平台，仍由组件和运行时的实际声明决定。

## 设备模块

打开 **组件库 → 设备模块**，搜索已安装模块的名称、标识或芯片范围，点击 **使用** 选择当前工程的平台，或点击 **导出 ZIP** 分享模块。列表每页显示 25 个模块。列表包含内置 `Esp32_S3_CAM`、`STM32F103C8T6` 和已安装的第三方设备模块。

内置模块在构建阶段生成独立 ESM 运行时，桌面发行包和 Web 发行包都包含这些资源；运行导出时无需源码、TypeScript 或 esbuild。内置模块的导出 ID 带 `_Module` 后缀，接收者可与内置平台并存；第三方模块保留自身 ID。

接收者在 **组件库 → 设备模块** 中选择 **加载 ZIP** 或 **加载文件夹**，核对模块信息后加载。新模块即时注册到宿主，随后按设备模块的信任流程启用；也可手动将包含 `manifest.json` 的模块目录放入宿主用户数据目录的 `plugins/` 后重启。模块开发和目录位置见[模块开发指南](RUNTIME-PLUGINS.md)。包内保留语言、界面和声明的工具资源，排除 `.uel`、本机编辑器设置、缓存与常见凭据文件。独立下载的 GNU、Arduino 等工具链通过下面的工具链入口交付。

## 离线工具

**首选项 → 编译与工具链** 提供按工具类型排列的版本列表、下载和离线导入；工程的编译器、语言版本和优化选项在 **生成 → 编译设置** 中选择。**首选项 → 工具链与导出** 显示本机已识别的工具、版本、路径和来源，并导出可迁移工具链。

下载目录和本机清单分别展示。未安装的新版不会覆盖本机已安装的旧版；系统 PATH 或自定义目录中识别到的工具也可导出，归档按工具类型收集可执行文件、动态库、目标库与头文件。

导出 GNU Arm、Arm Compiler、Arduino CLI、Arduino-ESP32、ST-Link 或 clangd 的已安装快照后，接收者可在“编译与工具链”中导入。Arduino 工具链保留包目录，导入时重新生成目标机器的目录配置。

### 下载、安装与选择

三种操作分别对应不同状态：

- **仅下载**：生成可保存和分享的离线 ZIP；本地可用工具列表不因此增加。
- **导入离线包**：从宿主电脑选择 ZIP，验证并安装到版本目录；不访问网络。
- **使用**：将已经识别的本地工具设为工程编译选择。

下载进度与安装进度保留在首选项的输出区域，下载完成显示为“离线包已下载”。关闭并重新打开首选项后，已下载工具包仍可再次保存。下载与离线安装均支持取消；未完成的下载和导入暂存目录会清理。

当前预设离线目录包含：

| 工具          | 版本                               |
| ------------- | ---------------------------------- |
| GNU Arm GCC   | 15.2.1-1.1、14.2.1-1.1、13.3.1-1.1 |
| Arduino CLI   | 1.3.1、1.2.2                       |
| Arduino-ESP32 | 3.0.7、2.0.17                      |

ST-Link 等系统安装工具仍在目录中提供其来源和安装方式，未将系统驱动安装伪装成可迁移离线工具。

### 归档格式与完整性

```text
blode-tool-package.json
payload/
├── 0-release.json
└── 1-publisher-archive.zip
```

工具清单包含 `format: "blode-tool-package"`、格式版本、工具 ID、目标平台／架构，以及每个 payload 的发布 URL、大小、SHA-256、角色和安装目的目录。已经压缩的发布归档以流式方式存入外层 ZIP，避免重新压缩整套工具。

已安装工具链的导出使用 `blode-tool-snapshot` 清单，按文件记录相对路径、大小、SHA-256 和权限。界面依次显示准备导出、收集文件、压缩和校验；收集阶段显示文件数，压缩阶段显示百分比。下载与安装使用各自的任务状态。

“工具链与导出”每次导出都会重新检测本地工具、遍历源目录并重新计算文件哈希，生成新的清单和 ZIP；保存对话框使用本次任务生成的归档。该页面不提供复用历史归档的入口。任务日志包含源目录、扫描目录、当前文件、清单文件数与总大小、压缩引擎、压缩进度、ZIP 大小、SHA-256、归档名称及总耗时；文件进度限频输出，避免大工具链产生大量重复事件。

Windows x64 内置 [7-Zip 26.05](https://www.7-zip.org/download.html) 独立命令行工具，创建标准 ZIP；工具缺失或执行失败时自动改用内置 ZIP 引擎，取消操作直接结束任务。其他宿主架构当前使用内置 ZIP 引擎。运行时无需另行安装 7-Zip。

构建脚本校验压缩工具和对应源码的 SHA-256，将 `vendor/7zip/` 中的工具、许可证及完整对应源码复制到 `dist/archive-tools/`，桌面和 Web 发行物均包含这些文件。宿主执行前再次校验工具并将其提取到宿主数据目录中的 `builtin-archives/`。上游来源、固定版本与许可证见 [7-Zip 运行时说明](../vendor/7zip/README.md)。

GNU Arm 和 Arduino CLI 使用预设版本的发布元数据与校验信息。Arduino-ESP32 使用 Espressif 和 Arduino 的包索引，并纳入该版本在目标平台上的全部 `toolsDependencies`；缺少编译器等必需依赖时停止导入。

导入会检查平台与架构、清单、文件集合、哈希、大小、解压总量和目录范围，拒绝目录穿越、Windows 保留文件名、大小写路径冲突、符号链接与硬链接。先在独立目录完成验证和安装，再原子替换目标版本；替换失败时还原原目录。SHA-256 用于检测内容变化，离线包本身不包含发布者的数字签名。

Windows 下仅对本次新安装的暂存工具树设置 Medium 完整性标签，不修改已有用户工具的属主或访问控制。路径先按真实目录校验，操作限定在该次安装目录内。

## 接口

| 宿主方法                 | 主要参数                                                      | 结果                                |
| ------------------------ | ------------------------------------------------------------- | ----------------------------------- |
| `projectPackagePreview`  | 无                                                            | 文件、外部依赖、工具需求与问题清单  |
| `projectPackageExport`   | `expectedProjectRoot`、`confirmExternal?`、`allowIncomplete?` | 导出 ID、名称和大小                 |
| `componentsExport`       | `expectedProjectRoot`、`ids?`、`confirm: true`                | 组件包信息、SHA-256、组件数量及依赖 |
| `componentsPackageSave`  | 导出 ID                                                       | 保存结果                            |
| `toolVersionDownload`    | `id`、`confirm: true`                                         | 离线包信息、SHA-256、平台和架构     |
| `toolVersionImport`      | 宿主绝对 `path`、`confirm: true`                              | 更新后的本地工具状态                |
| `toolVersionCancel`      | 无                                                            | 取消当前离线工具操作                |
| `toolVersionPackageSave` | 导出 ID                                                       | 保存结果                            |

Web 端通过现有受认证的下载入口取得导出文件。组件导出校验起始工程，工程切换后的迟到操作不会写入新工程。

## 验证范围

- Windows 上使用实际 GNU Arm 工具完成编译、打包、移走原外部头文件、异地解压和再次编译；两次二进制一致。
- 自动化覆盖命名目标、同名头文件、宏包含、Keil／CMake／Make 路径迁移、宿主模型凭据排除及大清单有界渲染。
- 组件集成测试覆盖递归依赖、自定义配置、空目录、修改后重新计算哈希、篡改拒绝、整包回滚及工程切换。
- 离线工具集成测试以固定发布归档夹具验证下载与安装分离、断网导入、ESP32 依赖闭包、哈希错误、平台不匹配、目录穿越、链接拒绝、取消及失败回滚。测试不下载整套真实发布工具。
- Linux 已有下载平台和架构选择，尚未在 Linux 机器上完成本批安装、解压和重建验收。包含符号链接或硬链接的发布归档当前会被拒绝，需要进一步适配后验证。
- 本批未构建桌面／Web 便携版，未进行硬件烧录或调试。

# Blode Studio

[简体中文](../README.md) · [繁體中文](README.zh-TW.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português](README.pt-BR.md) · [Italiano](README.it.md) · **Русский** · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

Blode Studio — модульная среда разработки встраиваемых систем: редактирование кода, сборка и прошивка, последовательная связь, аппаратная отладка, Git и совместная работа. Доступно приложение Electron или браузерный интерфейс к хосту Node.js на компьютере с проектами и устройствами.

[GitHub Releases](https://github.com/mioolio/blode/releases) · [CHANGELOG](../CHANGELOG.md) · [Issues](https://github.com/mioolio/blode/issues)

## Реализованные возможности

- Автодополнение C/C++, определения, ссылки, диагностика и форматирование через clangd; резервный индекс рабочей области, предварительные вкладки, разделённый редактор и восстановление черновиков.
- Сборка без подключённого устройства: именованные точки входа, Debug/Release, оптимизация размера и отдельный выбор инструментов C и C++.
- Экспорт BIN, HEX, S-record и ELF, запись готовой прошивки и передача проектов с внешними исходными зависимостями.
- Поиск библиотек Arduino, импорт папок и ZIP компонентов, экспорт модулей устройств и наборов инструментов для автономной работы.
- Просмотр регистров, дизассемблированного кода, стека вызовов и памяти; пошаговое выполнение и пакетное добавление точек останова.
- Общие вкладки, области редактирования и последние журналы; объединение независимых изменений с сохранением конфликтов. В браузере отменяются изменения текущего пользователя.
- Графическое управление историей Git, различиями, индексом, коммитами, ветками и удалёнными репозиториями; несколько системных терминалов и связь с VS Code.
- Просмотр изображений, воспроизведение аудио и видео; необязательное ИИ-дополнение и правки в выбранных границах. Модули и расширения содержат собственные ресурсы и языковые каталоги.

## Устройства и системы

| Модуль устройства                | Инструменты сборки               | Подключение         |
| -------------------------------- | -------------------------------- | ------------------- |
| Esp32_S3_CAM · ESP32-S3          | Arduino CLI + Arduino-ESP32      | UART / USB-JTAG     |
| STM32F103C8T6 · STM32F103C8/C8T6 | GNU Arm GCC / Arm Compiler 5 / 6 | ST-Link / SWD / GDB |

Текущие профили охватывают ESP32-S3 и STM32F103C8/C8T6. Выводы камеры задаёт проект. ESP32-S3 UART GDB проверен на эталонной конфигурации Windows; проверка встроенного USB-JTAG продолжается. Основной дистрибутив — Windows x64. Адаптации Linux x64/ARM64 и пользовательские пути инструментов macOS ещё не прошли полную проверку на реальных машинах.

## Быстрый старт

Для разработки из исходников нужны Node.js 24+, npm и Git.

```sh
git clone --single-branch https://github.com/mioolio/blode.git
cd blode
npm ci
npm run dev
```

Для браузерного интерфейса выполните команды на компьютере с проектом и оборудованием и откройте показанную ссылку. Выбор папок, сборка, USB, последовательные порты и терминалы выполняются на этом хосте.

```sh
npm run web:build
npm run web:start
```

## Модули и бинарные хосты

Модуль устройства разделён на десять областей: `support`, `device`, `runtime`, `constraints`, `ui`, `compiler`, `debugger`, `layout`, `languages`, `tools`. `be` хранит входные данные сборки, `blode.components.json` — библиотеки проекта. `package:runtime` создаёт независимые JavaScript, манифесты и ресурсы. Совместимые бинарные приложения и Web-хосты загружают их без TypeScript-исходников хоста. Обычные расширения могут добавлять оформление, меню, окна и нижние панели без реализации компилятора.

```sh
npm run package:runtime -- extensions/boards/Esp32_S3_CAM --output ./release/modules --zip
```

## Подписи пакетов

- `obe` — JSON-манифест с подписью Ed25519, связывающий издателя, ID/версию пакета, пути, размеры и SHA-256 всех файлов. Перед установкой фактическое содержимое проверяется повторно.
- Официальное доверие определяется реестром открытых ключей хоста. Отсутствующие или неизвестные подписи, повреждённая подпись и изменённые файлы различаются. Экспорт сохраняет подпись и не присваивает стороннему пакету официальный статус.
- Закрытые ключи остаются в `.signing/` вне Git и дистрибутивов. Windows Authenticode — отдельный уровень; текущий сертификат самоподписанный, а не выданный публичным центром сертификации. После изменения подписанного содержимого требуется новая подпись.

# 源码定位与外部头文件

## 使用

在 C/C++ 编辑器中选中函数、类型或宏，使用右键菜单的“转到定义”“转到声明”“转到引用”。`F12` 定位定义，`Shift+F12` 查找引用，`Alt+←` 返回；同名候选由编辑器的速览列表展示。

`#include` 路径也可以定位。例如在 `#include <esp_log.h>` 上使用 `F12`，会打开当前电脑已安装的 ESP32 SDK 头文件。外部源码使用只读标签；工程文件仍可正常编辑。网页端查找的是运行 Blode 服务的电脑。

右键菜单跟随界面语言，中文和英文切换无需重启编辑器。

拆分编辑时，跳转和返回保留各自分栏的位置。SDK 头文件更新后，速览和只读标签使用最新文本；刷新不产生未保存修改或撤销记录。

## 包含目录发现

宿主从以下信息收集实际存在的目录，不运行元数据中的命令：

| 来源            | 读取内容                                                       |
| --------------- | -------------------------------------------------------------- |
| 编译输出        | `.blode/build/` 的依赖文件、`compile_commands.json` 和响应文件 |
| 外部编译数据库  | 工程根目录或 `build/` 下的 `compile_commands.json`             |
| Keil 工程       | `.uvprojx` 的 `IncludePath`                                    |
| 工程组件        | `blode.components.json` 中的头文件目录及 Arduino 源目录        |
| Arm 工具链      | 已配置编译器的标准头文件目录                                   |
| ESP32 / Arduino | 已安装 core、所选芯片的 SDK `flags/includes`、core 和库目录    |

ESP32 core 版本来自工程编译设置；没有指定版本时查找本地已安装版本。安装索引存在时，按其工具依赖选择对应 SDK。ESP32-S3 读取 S3 的包含目录，不引入 S2 等其他芯片的 SDK 目录。

工程源码和未保存草稿先由编辑器的增量索引处理；宿主按包含关系读取外部头文件。引用结果使用当前草稿的位置替换同一工程文件的旧磁盘位置。

## 查询响应与取消

定义按名称增量索引，引用复用已解析文本和位置。并发查询共享头文件扫描，短时缓存未命中结果；缓存有数量上限，并在工程、编译配置或依赖变化后失效。扫描和引用匹配分批让出执行时间。

编辑器取消查询、修改文件、切换工程或关闭模型后，迟到结果不会继续创建模型或打开标签。多个调用共享同一查询时，取消其中一个不会影响其他调用；最后一个调用取消后，后续扫描停止。

Windows 本机对同一 ESP32 SDK 的 147 个头文件执行四个并发未命中查询：冷查询由约 178.8 秒降至 1.11 秒，事件循环最大延迟由 6132ms 降至 31.7ms；热索引下四个不同未命中查询约 0.50ms。这是宿主查询基准，不能作为浏览器界面帧率。前端索引的 400 文件基准中，128 次未命中定义查询由 187.429ms 降至 0.166ms，引用结果数量保持一致。

## 外部源码与接口

工作区索引使用 `language.index`，定位使用 `language.navigate`。桌面 IPC、Web 服务和自动化接口共用参数校验：

```json
{
  "method": "language.navigate",
  "params": {
    "expectedProjectRoot": "C:/work/camera",
    "path": "src/main.ino",
    "kind": "include",
    "specifier": "esp_log.h"
  }
}
```

`kind` 支持 `include`、`definition`、`declaration`、`reference`；后三种使用 `symbol` 字段。普通结果中的 `path` 为工程相对路径。外部结果附带宿主签发的 `externalId`，并使用 `@external/<id>/<文件名>` 作为标签身份。

可取消请求附带随机生成的 32 位十六进制 `requestId`。调用 `language.cancel` 时传入相同的 `expectedProjectRoot` 与 `requestId`。不传 `requestId` 的既有客户端仍可直接查询。

```json
{
  "method": "language.openExternal",
  "params": {
    "expectedProjectRoot": "C:/work/camera",
    "externalId": "由 language.navigate 返回的 ID"
  }
}
```

返回 `id`、`path`、`name`、`displayPath`、`content`、`language` 和 `readonly: true`。从已打开的外部文件继续定位时，传入其虚拟 `path` 和 `externalId`。宿主只接受已发现源文件的 ID；切换工程后，旧工程的请求会被拒绝。

读取限制为单文件 1 MB、外部索引最多 512 个文件和 12 MB。符号链接和目录联接不作为源文件读取通道。当前导航提供词法符号及包含关系定位；完整 C++ 类型推导、模板和预处理器分支解析仍由工具链或后续语言服务负责。

## 验证范围

自动化测试覆盖跨包含目录、含空格路径、递归头文件、声明与实现区分、多个同名头文件、引用位置、只读源文件身份、路径边界、取消、独立调用、缓存失效及工程切换。Windows 本机已使用安装的 ESP32-S3 SDK 验证 `esp_log.h` 和 `ESP_LOGI` 定位。

独立编辑器已验证中文菜单解析、F12 只读头文件定位和返回。Linux/macOS 工具目录发现、完整 C++ 语义以及不同工程的长时间使用继续验收。0.3.4.2 在本地构建，待用户手动创建发行版；本次产物检查见[发行说明](releases/0.3.4.2.md)。

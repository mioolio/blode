# Single public development port

The desktop development renderer already supported remote port 5173, but its API depended on a second fixed port. With external desktop sharing enabled, direct requests to 47821 required a token and returned 401 without it.

Development now gives the desktop API a random loopback port and publishes only port 5173. A separate Vite plugin forwards the seven API route families, including streaming events and downloads, without buffering them. The private endpoint is written atomically to ignored launcher metadata, cleared at startup/exit, and checked for a live owner and an exact loopback URL. Browser Origin is checked before rewriting the upstream Host and removing browser Origin/Referer headers. The proxy supplies the original public origin so all four extension/runtime window and ticket URL factories return addresses reachable by remote browsers. Only the private development backend accepts that header; standalone and packaged hosts ignore it. Production standalone host authentication is unchanged.

The Windows firewall helper defaults to 5173 and allows every remote address/network profile, matching the requested access scope. Runtime addresses and firewall state are machine-local and are not committed.

Validation: TypeScript checking passed. Ten development-server/proxy tests passed, covering LAN-style Host/Origin, JSON RPC, streamed SSE and cancellation, ranged resources, attachments, UI/debugger routes, invalid private targets and cross-origin rejection. Real backend integration also verifies public window/ticket URLs, one-use ticket consumption, overwritten spoofed forwarding headers and ignoring headers outside development proxy mode. An expanded existing Web suite passed 20 tests; its standalone component-import test failed with `error.packageApprovalRequired` (400 where the existing fixture expects 200). The standalone import/approval implementation is outside this change.

The actual development session was started using the development build mode. Requests through this computer's LAN interface returned HTTP 200 for the page, `getState`, `listRecentProjects`, and SSE, including its first streamed frame. Port 5173 listens on all IPv4 interfaces, 47821 has no listener, and the desktop backend listens only on a random loopback port. The original example LAN address is no longer assigned to this computer; the current address is reported to the user rather than stored in the repository. These checks originated on the host through its LAN address; another physical client was not available for an independent test.

The existing Node.js firewall allow rule permits inbound TCP from all remote addresses on the Public profile. The attempted administrator helper for an additional all-profile 5173 rule returned Windows authorization-cancelled, so that new rule was not applied and no retry was launched. The updated helper is ready to run later with administrator consent.

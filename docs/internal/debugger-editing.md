# 硬件调试：指令编辑与批量断点

状态：2026-10-30 内部开发更新，基于 `0.2.3.6-internal`。本次不生成正式发行包。

## 工作区

硬件调试窗口与浏览器标签共用顶部菜单：**连接、调试、视图、工具**。探针与 SWD 频率在 **连接 → 连接设置** 中选择，GDB 选择与安装收进 **工具**。工作区保留反汇编、寄存器、内存、调用栈和断点，不再使用大标题占据顶部空间。

内存面板右上角提供主按钮 **读取内存**。地址和长度集中在同一行，输入后也可按 Enter；SRAM、Flash、SP、PC 提供常用地址快捷入口。单次读取上限 4096 字节，需要目标暂停。

## 指令编辑

在反汇编行点击编辑按钮，选择 **汇编** 或 **机器码**：

- 汇编使用当前 GDB 同目录下的 GNU `as`、`ld`、`objcopy` 生成预览，按 Cortex-M3 Thumb 和目标地址编码。需要完整 GNU Arm 工具链。修改输入后须重新生成机器码。
- 机器码使用内存中的字节顺序，例如 `00 bf` 为 16 位 Thumb NOP。新旧指令必须等长，支持单条 16 位或 32 位 Thumb 指令。
- 汇编预览支持单条指令和数字跳转地址，不处理源码标签、外部函数名、指令块或文字池。生成预览不会写入硬件。

当前内置实现限定 `STM32F103C8T6` 的 SRAM：`0x20000000–0x20004fff`。这适用于放在 RAM 中执行的函数。常见位于 `0x08000000` 起始区域的 Flash 程序仍需修改固件后重新编译、烧录；本功能不会隐式擦写 Flash，也不会改动工程源文件或磁盘固件。

暂停时，写入前比较原机器码，写入后回读校验；只接受当前反汇编列表中的完整指令，不能从 32 位指令中间开始修改。运行时必须勾选 **短暂停止，写入成功后继续运行**：等待 GDB 的实际停止事件后再修改。遇到断点、异常停止、会话切换、原指令变化、写入或校验失败时，不自动继续。在恢复命令发出前接受的其他客户端暂停请求，会阻止自动恢复；恢复命令已发出但尚未确认时，新操作明确返回忙碌，完成后可再次暂停。

## 批量断点

从 **调试 → 批量断点** 或断点面板打开编辑框，每行一个位置，最多 128 项：

```text
main
main.c:20
*0x08000100
```

目标暂停时添加。每项独立返回 **已添加、已存在、添加失败**；单项失败不会撤销此前成功添加的断点。具体错误保留 GDB 的返回信息，硬件可用断点数量由目标与调试服务决定。

## 自动化与扩展

桌面 IPC、Web 宿主、JSON-RPC 和 MCP 共用校验：

| 接口                   | 参数                                                                           | 结果                         |
| ---------------------- | ------------------------------------------------------------------------------ | ---------------------------- |
| `debugger.assemble`    | `address`、`source`                                                            | 十六进制机器码预览           |
| `debugger.breakpoints` | `locations` 数组                                                               | 逐项位置、状态、ID 或错误    |
| `debugger.patch`       | `sessionId`、`address`、`expected`、`bytes`、`pauseAndResume`、`confirm: true` | 写前／写后字节及是否恢复运行 |

`sessionId` 从 `debugger.state` 获取，连接改变后需重新读取。第三方调试提供者可实现 `assemble`、`breakpoints`、`patch`；声明扩展内置 STM32 调试器且缺少对应方法时使用内置实现，完全替换模式不越过插件调用原生调试器。

## 退出修复

开发启动器不再因旧的渲染错误记录，把退出码 `0` 的正常关闭当作沙箱崩溃重启。真实启动故障仍保留一次恢复。退出时停止启动超时计时器，原生帧销毁后不继续发送界面事件；预期的取消操作通过受控响应返回，不再输出 Electron IPC handler 错误堆栈。

`GetGpuDriverOverlayInfo` 属于显卡驱动能力查询日志，与正常退出后的重复启动分开处理，本次未隐藏显卡诊断。

## 验证与验收

自动化覆盖汇编预览、MI 命令顺序、批量断点、写入比较与回读、暂停事件、会话变化、失败后保持暂停，以及启动退出分类和已销毁窗口事件发送。GNU 汇编测试调用 Windows 本机工具，使用固定机器码预期核对普通指令和不同地址的跳转。

尚未将模型化的 GDB 测试视为实机验证。物理 STM32／ST-Link 的 RAM 执行、运行中补丁和多客户端同时调试仍需实机验收；Linux 本次未验证。建议使用专门的 RAM 函数测试工程：

1. 暂停在 RAM 函数，分别用汇编和机器码修改等长指令，读取内存并查看反汇编。
2. 恢复运行，启用短暂停机修改，检查写入后恢复；另一个客户端同时请求暂停时应保持暂停。
3. 用不匹配的原机器码、Flash 地址及过期会话发起修改，确认拒绝且未写入。
4. 批量添加函数、行号和地址断点，混入无效位置，检查逐项结果。
5. 正常关闭开发窗口，确认启动器退出后不再次打开窗口。

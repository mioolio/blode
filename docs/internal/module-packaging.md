# 标准模块与独立分发更新

日期：2026-10-30。通道：`codex/runtime-plugins-internal`。基线：`0.2.3.6-internal`。

本次更新源码及开发契约，不发布新的正式版，也不生成桌面/Web 应用构建产物。模块打包测试仅在临时目录生成测试文件，结束后清理。

## 交付范围

`Esp32_S3_CAM` 与 `STM32F103C8T6` 统一为十个职责目录：`support`、`device`、`runtime`、`constraints`、`ui`、`compiler`、`debugger`、`layout`、`languages`、`tools`。实际编译、协议、模板、工具和布局代码按责任迁移，内部及仓库调用处同步更新。复用宿主的职责目录说明其声明与边界。

模块以 `manifest.languages` 声明固定语言或语言列表，拥有独立 C/C++ JSON 和 C 标准版本目录。编辑器、构建规则及 AI 状态接口使用当前模块数据；保留用户条目、工作区索引和工程规则。关闭内置补全不关闭用户工程的 JSON 条目。模块触发字符用于注册编辑器服务，普通输入复用解析缓存。

`package:runtime` 输出 JavaScript、声明、资源和文件摘要，可选 ZIP。标准平台默认输出不同于内置 ID 的 `_Module` 包，通过 `runtime` 编译模式执行包内代码；`managedTools` 声明其默认工具。生成包安装在兼容宿主的数据目录，运行时不引用主程序源码。

同时更新 ESP32-S3 调试后端、调试工具安装、架构界面和正常退出行为，详见[硬件调试](../HARDWARE-DEBUGGING.md)与[指令编辑更新](debugger-editing.md)。

## 兼容与迁移

| 项目           | 处理方式                                                                |
| -------------- | ----------------------------------------------------------------------- |
| 已有工程 ID    | 保持 `Esp32_S3_CAM`、`STM32F103C8T6`；旧别名继续迁移                    |
| 平台源码导入   | 更新为 `device/`、`runtime/`、`compiler/`、`layout/`、`tools/` 下的入口 |
| 第三方发行包   | 使用 `.mjs`/`.cjs` 入口；不把 `.ts` 或源码 registry 交给使用者          |
| 旧正式版二进制 | 先由维护者分发包含本次更新的宿主，再安装使用新字段的模块                |
| 插件授权       | `.uel` 不分发；换机器、移动位置或更新内容后重新确认                     |
| 工具           | 不把开发者绝对路径写入包，下载工具与可写状态使用宿主数据目录            |
| Linux          | 提供路径、下载资产及 ZIP 执行位适配，尚未在 Linux 实际运行              |

交叉审查修复了 STM32 工厂参数不匹配、打包后静态 URL 偏移、HTML 外部资源产生空白视图、ZIP 丢失可执行权限、关闭默认补全误删项目条目，以及对非 C 语言误用 C 语义规则的问题。

Windows 已额外完成 Espressif 两份官方工具归档的实际代理下载、SHA-256 校验、解压及 GDB/OpenOCD 版本执行。未连接或写入物理硬件。

## 用户验收

1. 打开已有 ESP32/STM32 工程，检查语言补全、标准切换、离线编译及工具版本。
2. 切换两个平台，确认 Arduino 清单不出现在 STM32 模块中，用户 AI 条目仍保留。
3. 修改项目语言规则，检查错误定位、默认清单开关与输入响应。
4. 在没有源码目录的兼容桌面/Web 宿主中安装独立包，授权后测试资源和离线构建。
5. 对真实目标逐项验证识别、烧录、JTAG/SWD、断点、内存和重连；记录工具与硬件版本。
6. 完成 Linux 下载、执行权限、动态库、USB 和真实编译检查后，再更新平台支持级别。

# Windows 开发启动恢复

日期：2026-10-30。分支：`codex/runtime-plugins-internal`。本次更新启动脚本与 Vite 配置，不生成应用发行包。

## 问题与原因

现场日志显示，第一次启动的渲染进程在创建窗口后以 `-2147483645`（`0x80000003`）崩溃，随后页面加载返回 `ERR_FAILED`。主进程处理该错误并调用退出流程，因此终端显示的 Electron 主进程退出码仍为 `0`。判断恢复方式需要同时读取渲染器和主进程日志。

第二次兼容启动期间，模块语言校验首次引入的 `zod` 触发 Vite 新依赖优化和整页刷新。现场第二次日志记录了后台服务就绪，但没有界面挂载标记；随后进程以 `0xC000013A` 中断退出。

## 修复

- 在 Vite 第一批预优化中加入 `zod`，延迟加载语言规则和编辑器时保持依赖版本稳定。
- Windows 开发启动默认采用 `auto` 策略：首次已知沙箱崩溃可以恢复一次；兼容模式真正挂载界面后保存本机结果，下次直接复用。
- 记录绑定 Electron 版本、程序路径和配置目录，位于当前工作区 `.tools/`。版本或路径改变后重新检测。
- 普通关闭、超时、额外软件渲染回退和没有实际界面就绪的尝试不会保存兼容结果。
- 就绪判定仅接受主进程启动标记，避免把控制台文字当作已显示界面。
- `BLODE_DEV_SANDBOX=required` 强制使用沙箱；`disabled` 显式选择兼容模式。详见[开发说明](../DEVELOPMENT.md#windows-开发启动兼容)。

AMD `GetGpuDriverOverlayInfo` 属于图形驱动能力查询日志，启动器继续依据实际界面挂载、崩溃和超时状态判断恢复。

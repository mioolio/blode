# Blode Studio 0.2.3.6

版本日期：2026-10-29

0.2.3.6 将编辑、语言规则、工程配置、版本管理、团队协作与硬件工作流整合为同一工作台，并提供桌面便携版和独立 Web 版两种交付方式。

## 发行产物

| 产物                                       | 内容                                              | 使用环境                |
| ------------------------------------------ | ------------------------------------------------- | ----------------------- |
| `Blode.Studio-0.2.3.6-desktop-win-x64.exe` | 轻量桌面便携程序、Electron 运行时、界面与宿主服务 | Windows x64             |
| `Blode.Studio-0.2.3.6-web.zip`             | Node 宿主、浏览器界面、运行时依赖清单及文档       | 服务端 Node.js 24+、npm |
| `SHA256SUMS.txt`                           | 本轮发行文件的 SHA-256 摘要                       | 校验下载完整性          |

本地构建目录为 `release/0.2.3.6/`。桌面和 Web 包均不捆绑完整 SDK 或授权编译器。工具可通过首选项安装、按版本选择，或指定目标机器已安装的工具路径。Arm Compiler 的使用和分发仍遵循其自身许可证。

本轮 Windows 桌面包为**未代码签名构建**。请从项目发布渠道获取，并使用随附摘要核对文件。

对外发行号与文件名使用 `0.2.3.6`。npm 工具链要求合法的三段语义版本，因此清单的 `version` 为 `0.2.3-6`，另以 `releaseVersion: "0.2.3.6"` 保存发行标识；Windows 构建版本使用四段值。Web 运行时清单沿用相同映射。

## 新特性详解

### 代码导航与索引

在函数、宏、类型或变量上通过右键与 F12 查找定义或声明；头文件包含路径可打开关联文件。多个候选通过编辑器列表预览和选择，Alt+Left 返回导航来源。跨文件跳转保留目标选区。

索引按文件内容增量更新，覆盖工作区可读取的 C/C++ 文本。未保存草稿直接参与编辑器导航和补全；保存源码的派生导出位于 `.blode/index/symbols-v1.json`。该缓存可重建，不作为编译输入选择的依据。外部 AI 可通过 `language.index` 取得源位置。

当前索引基于词法提取；宏展开、模板重载、跨 SDK 类型推导等完整语义功能仍由编译器或未来语言服务处理。详情见[语言规则](../LANGUAGE-RULES.md)。

### 分版本 JSON 补全和规则

C99、C11、C17、C23 使用独立目录，不跨版本继承默认数据。每个版本包括：

- `a.json` 至 `z.json`：按函数名首字母组织的标准库条目。
- `keywords.json`、`types.json`：关键字、类型和常量。
- `control-flow.json`：分支、循环等代码片段。
- `rules.json`：标识符与函数调用检查。
- `manifest.json` 和 `catalog.ts`：版本文件清单与显式注册。

工程可在 `languages/C/<标准>/` 下覆盖默认条目。JSON 解析、字段、版本与重复配置错误显示具体路径和行列；配置错误阻止构建。源规则默认使用 warning，用户可改为 error。用户和外部 AI 的补全清单继续生效，显式 `c` 项优先于兼容的 `cpp` 项。

规则包与配置诊断复用缓存，普通输入只重新检查发生变化的已加载文件；编译前执行工程规则检查。

### 工程高级设置

右键根目录 `be` → **高级设置**，通过表单配置名称、平台、入口、显式文件清单和 C 标准，右侧显示即将保存的 JSON。保存复用现有配置校验和共享工程写入流程；配置在其他位置更新时要求重新读取。

`build.cStandard` 可选 `c99`、`c11`、`c17`、`c23`。STM32 构建传入相应 GNU 方言参数，ESP32 的显式 C 标准通过 Arduino 的 C 编译属性传递；C++ 编译标准由相应平台构建逻辑维护。较旧工具对 C23 的支持可能不同，应根据工具错误选择标准或编译器版本。

### 分层编译设置

**运行 → 编译设置** 提供通用、STM32、ESP32-S3 导航和平台内的通用／C／C++ 选择。设置保存在 `be.build.settings`，按通用、平台、语言顺序解析；`inherit` 跟随上级，`auto` 在目标机器自动查找兼容工具，也可选择已安装版本或填写自定义路径。

已安装清单表示本机实际可用工具；可下载版本目录与安装操作保留在首选项。编译设置本身不下载工具，也不要求连接设备。缺少明确版本时需要安装该版本或修改工程选择。

STM32 的 C/C++ 可使用同系列的不同版本；GNU Arm 与 Arm Compiler 6 不能在同次构建中混用。包含 C++ 时使用 C++ 所选工具链链接。ESP32-S3 在一次 Arduino 构建中使用一致的 CLI 与 core 环境。

两个平台的调试模式使用 `-O0 -g`，发布模式默认 `-Os -g`，关闭体积优化时使用 `-O2 -g`。GNU Arm 与 Arduino 链接传入未引用段清理参数，Arm Compiler 6 按调试／发布选择保留／移除未引用代码。自动检查覆盖配置、工具选择和命令构造，另有下文记录的真实 GNU 混合语言编译；Arduino core 配方的真实工程与硬件结果仍待验证。设置示例和迁移方式见[工程与编译设置](../PROJECTS.md)。

### 独立 Git 与团队管理

软件自身历史默认位于 `.blode/git`，与项目现有 `.git` 的索引、分支、身份和配置分开。图形界面支持状态、差异、暂存、提交、分支、远端与身份设置；命令面板继续保留。

- **独立模式**：本软件维护自己的版本历史。
- **共享模式**：用户主动开启后，使用工程已有仓库，与其他 Git 工具协作。
- **停用管理**：停止工作台的 Git 管理，保留源文件与历史。
- **删除软件历史**：仅移除本软件拥有的仓库元数据。
- **删除共享历史**：选择共享目标并输入精确的仓库根目录，再确认执行。

操作关闭 hooks、fsmonitor 与自动签名，清除继承的 Git 目录／索引环境变量；拉取采用快进方式，推送发送到明确分支。删除历史不执行源码回滚。详见 [Git 管理](../GIT.md)。

### 多人协作与编辑状态

浏览器保存自己的身份与颜色，标签显示协作者，代码区标注阅读／编辑范围。文件与资源布局、AI 等工具标签可同步显示，新标签不抢占当前页面。

独立修改合并，重叠修改显示冲突。网页撤销与重做只处理自己的变更；本地桌面保留全局操作能力。远端文本更新尽量维持阅读锚点，选区使用平滑过渡；系统减少动画偏好会关闭对应过渡。

未保存标签关闭时提供保存、放弃和取消。标签关闭、页面离开或刷新时释放阅读状态，迟到消息按会话归属处理。编译日志只重放最近一轮，避免刷新后重复堆积全部历史。

### AI、工具与工程交付

外部 AI 与手动设置共用补全清单，覆盖、禁用、成员提示及工作区符号保持一致。预测提示默认关闭；启用后外部 AI 读取带版本的上下文并提交建议，Tab 接受建议，继续输入使旧建议失效。软件不要求配置模型服务密钥。

首选项采用左侧导航与右侧配置，提供工具版本目录、自定义路径、下载进度和第三方安装输出。工程 ZIP 导出收集受支持的外部依赖，改写归档副本，生成依赖清单。

可迁移 ZIP 同样处理新编译设置：保留模式、体积优化、编译器系列和版本，移除各层本机绝对工具路径，并在清单记录相应工具要求。接收者可使用本机并行安装的版本，或通过编译设置重新选择工具；原工程配置保持不变。

修复了 GNU Arm 安装完成后仍显示未安装的状态问题。工具链状态分别检查 GNU Arm 与 Arm Compiler 的安装事实和版本，并识别并行安装的 `tools/versions/gnu-arm` 目录；“已安装”与“当前工程选用”分别表示工具可用性和构建选择。此次状态修复保留现有编译器选择顺序。

硬件功能包括串口 UTF-8／HEX 通信、固件多格式导出、无工程固件烧录，以及独立 STM32／ST-Link／GDB 调试界面。硬件工作台读取真实目标的暂停采样，显示寄存器、指令、内存、断点和 ELF 文件内容。

### 启动和界面响应

窗口首屏与服务初始化并行；硬件及工具状态首次后台检查，界面显示检查状态。编辑器、首选项及其他工具页面按需加载，编辑器准备期间显示真实源码预览。

开发启动仅检查 Electron 和构建器的关键可执行文件，工具目录全量检查保留在安装和手动修复流程。权限检查在构建前完成，覆盖此前遗漏的 esbuild Low 完整性标签。Vite 从主页面扫描依赖，并忽略工具、缓存和产物目录。

终端逐阶段显示耗时，长等待每 5 秒报告当前阶段。失败的 Electron 尝试保留日志。可运行：

```sh
npm run dev -- --diagnose-startup
```

诊断使用独立 profile、端口和依赖缓存，不启动桌面窗口。准备时间和首个 HTML 响应不能直接当作完整桌面冷启动时间。日志与恢复机制见[开发说明](../DEVELOPMENT.md)。

大弹窗移除了背景模糊重绘；同时调整 CSS 声明顺序，保留发布压缩后的标准属性。目标设备、资源统计、串口和调试器文案删除重复说明，保留状态与实际错误。

## 安装

### 桌面版

1. 核对文件 SHA-256。
2. 在 Windows x64 的可写目录运行桌面便携 EXE。
3. 打开工程，选择工具链和 Git 管理方式。
4. 编译前通过 `be` 高级设置确认入口和标准，在 **运行 → 编译设置** 选择模式和本机工具；硬件操作前识别设备。

本次包不包含所有工具链。工具下载和安装进度显示在首选项，已有工具可以通过自定义路径复用。

### Web 版

1. 在目标电脑安装 Node.js 24+ 与 npm，并将 ZIP 解压到可写目录。
2. 执行 `npm ci --omit=dev` 安装适合该系统的 serialport 运行时依赖。
3. 执行 `npm start`，打开终端输出的私密链接。
4. 共享至可信局域网时使用 `npm start -- --host 0.0.0.0 --port 47821`。
5. 按 Ctrl+C 停止服务。

工程、编译器、Git、固件、ELF 与硬件设备都属于服务电脑。参数、数据目录与部署说明见 [Web 宿主](../WEB-HOST.md)。

### 校验文件

在发行文件所在目录，PowerShell 可计算摘要：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\Blode.Studio-0.2.3.6-desktop-win-x64.exe
Get-FileHash -Algorithm SHA256 -LiteralPath .\Blode.Studio-0.2.3.6-web.zip
```

逐项与随产物生成的 `SHA256SUMS.txt` 比较，核对内容完整性。发布者签名状态见实际产物与发行记录。

## 升级与迁移

1. 保存工程并退出旧桌面版，或停止旧 Web 服务。
2. 备份源码、`be`、`languages/`、用户需要保留的版本历史和宿主数据目录。使用独立 Git 时包含 `.blode/git/`；索引与构建缓存可以重建。
3. 将新版本放入新目录。Web 版在新目录重新运行 `npm ci --omit=dev`，需要沿用设置时继续使用原 `--data-root`。
4. 打开工程，选择 Git 管理方式与语言标准。
5. 重新编译并核对产物，再执行烧录或调试。

| 原有内容                        | 迁移行为                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `be` 与旧 `.blode/project.json` | 继续读取；建议以高级设置检查并保存当前配置                                    |
| `blode.completions.json`        | 继续参与工程补全；新规则建议迁入按标准划分的目录                              |
| 项目已有 `.git`                 | 未自动启用；需要旧历史时明确选择共享模式                                      |
| 软件独立历史                    | 使用 `.blode/git`，不会自动导入已有 `.git` 的提交                             |
| 旧构建产物                      | 构建指纹和默认 C 标准路径已有调整，升级后重新编译                             |
| 索引缓存                        | 由当前源码重建；不用于选择真实构建输入                                        |
| `build.settings`                | 新增分层构建配置；未配置时沿用工程原有工具解析，分享 ZIP 清理本机绝对工具路径 |
| 开发版数据                      | 默认 `.tools/dev-user-data`，与安装／便携版和 Web 宿主数据区分                |

编译工作不要求设备在线；烧录、串口与硬件调试需要目标机器能够访问对应设备。

## 验证记录与已知范围

本轮开发阶段执行了类型检查、桌面和 Web 构建、语言规则／索引／编译预检查、临时 Git 仓库、协作、源码索引边界、工程打包和 HTTP 服务测试。隔离工程界面检查验证了 F12 重复候选、跨文件跳转、头文件关联、返回行列与高级设置保存。

Windows 本机使用真实 GNU Arm GCC 15.2.1 编译了独立的混合 C/C++ 小工程，`g++` 实际执行 C++ 编译和最终链接。三种模式均成功：

| 模式           | Flash 占用 | 单次耗时 |
| -------------- | ---------- | -------- |
| Debug，`-O0`   | 636 B      | 909 ms   |
| Release，`-Os` | 580 B      | 589 ms   |
| Release，`-O2` | 616 B      | 562 ms   |

这些数值仅描述该小样例。测试未使用用户工程或连接硬件，耗时不作为其他工程的性能承诺。本机工具发现检查耗时 361 ms，识别出 AC6 6.22、托管 GNU 15.2.1、并行安装的 GNU 15.2.1-1.1，以及 Arduino CLI 1.5.2-rc.1／ESP32 core 3.0.7。发现工具表示安装可用性；AC6 实际编译、ESP32 实际工程、硬件操作及 Linux 本轮均未验证。

发行产物的最终摘要、文件大小和打包验证结果随构建输出提供。平台与功能的验证范围如下：

| 范围             | 当前状态                                                                     |

| Linux x64／ARM64 | 已提供 Node 路径和部分工具下载适配；未在 Linux 实机安装、编译或连接硬件验证  |

# Blode Studio 0.3.4.2

构建日期：2026-10-30

0.3.4.2 整合 AI 服务与补全、源码导航性能、多入口编译、离线交付、通用扩展和协作工作台改进，提供 Windows x64 桌面便携版与独立 Node.js Web 版。

界面和产物版本为 **0.3.4.2**，npm 清单版本为 **0.3.4-2**。

[主要说明](../../README.md) · [更新记录](../../CHANGELOG.md) · [平台支持](../PLATFORM-SUPPORT.md) · [验收记录](../internal/workspace-improvements.md)

## 发行文件与运行条件

输出目录为 `release/0.3.4.2/`，附发行说明和 SHA-256 校验文件。

| 文件                                       | 内容                                          | 运行条件                                              |
| ------------------------------------------ | --------------------------------------------- | ----------------------------------------------------- |
| `Blode.Studio-0.3.4.2-desktop-win-x64.exe` | 桌面便携程序、Electron 和应用运行时           | Windows x64；可写的工程与用户数据目录                 |
| `Blode.Studio-0.3.4.2-web.zip`             | 独立服务端与浏览器界面，无 Electron／Chromium | 目标电脑安装 Node.js 24+ 与 npm；客户端使用现代浏览器 |
| 校验文件与 `0.3.4.2.md`                    | 文件摘要与可用于手动发布的发行说明            | 对照最终构建目录中的文件                              |

桌面版启动无需另装 Node.js。两种版本均按需配置编译器与 SDK，本次轻量产物不内置完整工具链。Git 操作需要目标电脑安装 Git；串口、烧录和调试使用目标电脑的驱动与设备权限。编译不要求连接开发板。

当前标准运行时为 `Esp32_S3_CAM` 和 `STM32F103C8T6`：前者使用 ESP32-S3 的 Arduino 编译与烧录流程，摄像头引脚由工程配置；后者面向 STM32F103C8／C8T6。其他型号由运行时模块声明支持范围。

## 主要更新

### AI 服务与全输入补全

- 首选项支持 DeepSeek、通义千问、硅基流动及自定义兼容接口，分别选择聊天与预测模型。密钥保存在宿主加密凭据存储，公共配置只显示是否已保存。
- 右键“AI 补全”或按 `Ctrl+Alt+Space` 请求一次，自动模式关闭时也可使用；`Ctrl+Space` 保留为常规代码补全。
- 自动 AI 补全默认关闭。开启后，代码、`//这是什么` 等中文注释、字符串、普通文本、单字、空格和换行都能触发，不按语言或最少字数筛选；输入法组合结束后再计时。
- 输入间隔默认 750ms，可设为 100–10000ms。按 `Tab` 接受完整灰色建议，撤销恢复；继续输入或切换上下文使旧建议失效。
- 编辑区显示生成、无建议、缺少密钥、超时和服务错误状态；空响应立即结束，失败重试清除上一条建议。
- 选区、文件与工程问答／修改使用右侧 AI 面板；目标电脑操作需要明确授权。原有外部 AI 清单和预测接口继续兼容。

详见 [AI 补全与模型服务](../AI-COMPLETIONS.md)。

### 源码导航与查询性能

- C/C++ 定义、声明、引用与头文件定位覆盖工程草稿及真实编译器包含目录；外部 SDK 源码以只读标签打开。
- 定义按名称增量索引，引用复用已解析位置；SDK 扫描合并并发请求、限制 I/O，并缓存未命中结果，减少反复查询不存在符号时的重复工作。
- 多个调用独立取消；工程、模型版本或配置改变后，迟到结果不继续打开标签。
- 修复分栏与 Peek 的目标归属和返回位置；SDK 头文件变化后更新只读预览内容与定位行号。
- 中文菜单保留编辑器命令、快捷键和同名候选列表。

Windows 固定基准中，同一 ESP32 SDK 的 147 个头文件、四个并发未命中查询由约 178.8s 降至 1.11s，事件循环最大延迟由 6132ms 降至 31.7ms。前端索引 400 文件的 128 次未命中定义查询由 187.429ms 降至 0.166ms。这些是查询基准，不是浏览器界面帧率。

详见 [源码定位](../SOURCE-NAVIGATION.md)。

### 命名编译入口与工具选择

- 同一工程可建立多个命名入口，分别设置源码根目录、运行时、语言、编译器版本、缓存和产物。
- 单入口或默认入口直接编译；多入口从“生成”菜单选择，支持长列表滚动与键盘操作。
- 通用、平台与 C／C++ 分层选择工具，区分本地已安装、可下载和工程选用版本；支持调试／发布及固件体积优化。
- 调试按成功构建及 ELF 哈希关联当前入口，手动选择优先；入口、文件或构建失效时清理旧关联。
- 开发启动遇到默认端口占用时选择后续端口，桌面与重试使用本轮服务地址并校验实例。

详见 [命名编译入口](../BUILD_TARGETS.md)与[工具版本](../TOOL-VERSIONS.md)。

### 组件库与离线工程交付

- 组件库支持搜索、本地状态、详情、Arduino 依赖解析、目录／ZIP 导入和移除。
- 组件 ZIP 保留当前源码、自定义包含目录与源码配置、空目录及递归依赖；批量导入失败回滚。
- 工程 ZIP 使用成功构建的实际依赖，收集工程外文件并改写归档副本，原工程不变。
- 工具支持仅下载、保存离线包、离线导入、进度与取消；下载、安装和工程选择分别显示。
- 离线导入检查摘要、平台、目录边界与必需文件，安装采用原子替换及失败回滚。

详见 [组件库](../COMPONENT-LIBRARIES.md)、[工程打包](../PROJECT-PACKAGING.md)与[离线交付](../OFFLINE-DELIVERY.md)。

### 媒体、多终端与工作区

- 图片支持滚轮锚点缩放、拖拽和适应窗口；音频与视频可播放，视频支持跳转与 Range 读取，关闭后释放资源。
- 新增、切换和结束独立 PowerShell／系统 Shell 会话，支持终端标签滚动与对应进程释放。
- Git 采用紧凑的差异、暂存与提交布局，大差异有界渲染；命令窗口保留。
- Flash／RAM 与工程文件统计合并到底部资源页；运行时和设备操作集中到项目资源左下折叠区。
- 干净工程直接关闭或返回首页；有实质修改时选择保存、放弃或取消。桌面默认关闭到托盘，可在配置中调整。
- “更多操作 → 在 VS Code 中打开”生成工作区配置，在目标电脑启动 VS Code，磁盘变更通过工程监听同步。

详见 [资源预览](../ASSET-PREVIEW.md)、[Git](../GIT.md)与[VS Code 连接](../vscode.md)。

### 通用扩展与个性化示例

- `kind: extension` 与设备运行时分开管理，不出现在目标设备列表。
- 支持目录／ZIP 审查安装、权限查看、启停、设置、卸载和分享。
- 扩展可声明菜单显示、主题变量、背景、透明效果、原生窗口／Web 标签页及底部功能区。
- 原生代码按明确授权和包指纹加载；停用恢复界面贡献，包变更后重新审查。
- 官方 Personalization 示例包含自有 ESM、语言清单、样式、设置、资源、权限和文档，可复制后独立分发。

详见 [通用扩展开发](../GENERAL-EXTENSIONS.md)与[运行时插件](../RUNTIME-PLUGINS.md)。

### 桌面与 Web 协作一致性

- 文件、工具、插件底部页及面板使用统一注册入口；共享标签出现时不抢占另一位用户的当前页面。
- 跨端关闭处理保存／放弃／取消，并按共享版本提交；断线重连与迟到消息不恢复已关闭标签。
- 头像紧凑堆叠，阅读与编辑区域使用各自颜色；后台页面停止广播正在阅读的标记。
- 本地草稿、共享修订、外部磁盘保存和按用户撤销分别处理；冲突进入合并流程。
- 编译日志只同步最近一轮，刷新恢复相关工作区状态。

详见 [多人协作](../COLLABORATION.md)。

## 运行与升级

### Windows 桌面便携版

1. 校验 EXE 摘要并运行。
2. 打开工程，在“生成”菜单选择入口与工具；已有工具可通过路径复用，也可从首选项安装。
3. 使用串口、烧录或调试时，连接目标设备并配置驱动。

升级前保存工程并退出旧程序，新版本放入独立目录。保留源码、`be`、语言规则与需要的 Git 历史，索引和构建缓存可以重建。

### 独立 Web 版

在拥有工程和硬件的目标电脑解压 ZIP，进入该目录：

```sh
npm ci --omit=dev
npm start
```

打开终端输出的私密链接。可信局域网访问使用：

```sh
npm start -- --host 0.0.0.0 --port 47821
```

文件选择器、Git、编译器与硬件设备都属于服务电脑。按 `Ctrl+C` 停止服务。升级时在新目录解压并安装运行时依赖；需要沿用设置时使用原 `--data-root`。详见 [Web 宿主](../WEB-HOST.md)。

Web 包在目标系统安装 SerialPort 与 node-pty 运行时依赖。Linux 路径和下载已有适配，但 Linux 安装、原生依赖编译、USB 权限及硬件流程尚未实机验证；macOS 未验证。

# Blode Studio 0.3.4.5

本次更新把 Web 版改为单文件 Windows 可执行程序：目标电脑不需要 Node.js、npm 或源码，运行后直接在浏览器中使用同一套工作台；同时重新打包桌面便携版，并修复两个导致窗口一闪而过的问题。

## 变更

- `npm run package:web` 现在生成 `Blode.Studio-0.3.4.5-web-win-x64.exe`，内嵌 Node 24 宿主、浏览器资源、SerialPort 与 node-pty 原生运行时；不再生成需要 `npm ci --omit=dev` 和 `npm start` 的源码 ZIP。
- 可执行文件约 96 MiB，比桌面便携版（约 132 MiB）小约 27%，不包含 Electron、Chromium、编译器、驱动归档或工程文件。
- 首次启动把运行时解压到宿主数据目录的 `runtime/bundle-<内容哈希>/`，后续启动直接复用；目录名绑定载荷哈希，升级版本不会覆盖或混用旧运行时。
- 启动后自动用默认浏览器打开带一次性令牌的私密链接；`--no-open` 只输出链接，`--version` 输出版本号。`--host`、`--port`、`--project`、`--data-root` 与源码宿主完全一致。
- `--help` 不写入磁盘，直接打印源码宿主与打包版共用的选项说明。

## 修复

- Web EXE 从低完整性构建目录生成时会继承 Low 完整性标签，双击后以低权限运行、无法写入 `%LOCALAPPDATA%`，进程在打印启动链接前退出，窗口一闪而过。打包现在把产物恢复为 Medium 完整性标签。
- 桌面便携版使用隔离构建目录时 `app.asar` 漏掉 `dist/renderer`，启动后无法加载界面。打包现在复制完整 `dist/`，并在发布前校验归档包含 `dist/renderer/index.html`。
- 启动器遇到错误时会在交互式控制台保留窗口并提示检查数据目录，不再立即关闭。

## 下载

- **桌面便携版**：Windows x64，直接运行 EXE（0.3.4.5 重建）。
- **Web 版**：Windows x64 单文件 EXE，运行后使用浏览器访问；目标电脑无需安装 Node.js。

## 验证

- 本机用多个全新数据目录重复启动构建产物：每次都完成解压并打印启动链接；缓存目录再次启动时跳过解压。
- 打包宿主的 `/?token=` 页面与静态资源返回 200，未携带令牌的 RPC 返回 401，`getState` 返回工程状态，交互终端命令以 exit code 0 结束。
- 桌面便携版启动后出现标题为 “Blode Studio” 的窗口并保持响应，归档包含 54 个 renderer 文件。
- 无参数（默认数据目录）启动在恢复 Medium 完整性后可正常解压并打印启动链接；缓存目录再次启动跳过解压。
- 已检查 `--help`、`--version`、载荷哈希目录和发行版本号；未验证跨机器复制、长时间会话，以及 Linux／macOS 打包。

# STM32F103C8T6 128 KiB 实机案例

这是一个真实烧录过的示例工程：一块常见的 STM32F103C8T6“Blue Pill”在 `st-info` 中报告 **128 KiB Flash / 20 KiB SRAM**，而不是通常标称的 64 KiB。固件包含 **72 KiB** 的已知图案，编译后 `.bin` 为 **75,888 字节**，超过 64 KiB 边界；烧录后从 `0x08010000` 读回 `0xA5A5A5A5`，证明该芯片的 64 KiB 以上区域确实可读写。

完整过程、命令输出与验证结论见 [SHOWCASE.md](../../SHOWCASE.md)。

## 这个工程验证什么

- `src/flash_70k.c` 放置 72 KiB 的 `0xA5` 常量图案，并在 `flash_70k_selftest()` 中读取 `0x08010000`。
- `src/main.c` 初始化 USART1（PA9/PA10，115200 8N1）和 PC13 LED，弱调用自检函数；如果串口已连接，会打印 `128KB OK` 或 `64KB only`。
- `be` 把物理容量和应用区都设为 `131072` 字节，并写入 `flashSizeOverride: true`，用于纠正/覆盖被错误报告的容量。

## 使用

1. 用 ST-Link 连接 SWDIO、SWCLK、GND，并给目标板供电。
2. 在 Blode Studio 中打开本目录的 `be`。
3. 点击“识别芯片”，确认 ST-Link 报告 `131072`（128 KiB）和 `0x410`。
4. 在“资源布局”中确认应用区为 128 KiB；如果芯片实际只有 64 KiB，构建应因 72 KiB 图案超出而失败，这是预期保护。
5. 构建后烧录。串口接 PA9/PA10 可看到自检输出；没有串口时，也可用 `st-flash read` 验证 `0x08010000`。

> 注意：不是每一颗标称 STM32F103C8T6 的芯片都能稳定使用 128 KiB。只有实测通过写入、回读和运行验证的单元才应这样配置；不要把本案例当作所有 C8T6 都具备 128 KiB 的保证。
